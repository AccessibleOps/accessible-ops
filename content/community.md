Accessible Ops is a living spec, and it gets better by being argued with.

The work happens in the open on [GitHub](https://github.com/AccessibleOps/accessible-ops). Open an issue to propose a property, challenge one, or sharpen the wording. Send a pull request if you already have the change in hand. The bar for a property is the bar the rest of them clear. It has to hold for a person and for an agent, and it has to be something you can point at rather than a preference.

The most useful thing you can bring is evidence. If you have built something that meets these properties, or found where they fall short in practice, that carries more weight than an argument. The list is meant to describe what works.

Adopt it or adapt it. The list is more useful the more places it turns up.
